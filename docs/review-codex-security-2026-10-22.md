# Independent toolbox security review, 2026-10-22

Reviewed baseline: `4633c883559fca708b93f39dabf6703b3a43ca7a`, branch `pr/19-toolbox-hardening`, Windows/NTFS. All baseline line numbers below refer to that commit, before remediation. Reproductions are synthetic and run in disposable directories; no AI provider, real CLI configuration, or permission store is used. Existing assertions and route/state fixtures are unchanged.

## Findings

Counts (confirmed / refuted): critical **1 / 1**, high **8 / 2**, medium **6 / 3**, low **1 / 0**. Severity describes the attempted attack, including for refuted findings. A successful marker-writing fsmonitor command is classified critical because merely building project context executes repository-controlled code with the user's rights.

The regression names below identify executable reproductions in the committed test files. New regressions were run against the baseline source and observed failing, then against the patched source. The native 8.3 and POSIX-only checks have the explicit limitations listed below.

## Additional checks that passed

- Worker termination bounds the existing catastrophic search pattern `^(a+)+$`; invalid and overlong patterns are rejected. The glob deadline now has its own regression.
- Binary, oversized and directory reads are refused. Read ranges remain capped at 800 lines, tool text at 60,000 characters, Git subprocess output at finite buffers and Git execution at finite timeouts.
- `.ENV`, `.env.local`, `.env~`, `credentials.json`, `.git-credentials`, `.netrc`, `.pypirc`, `.aws/credentials`, `.SSH/config`, private-key formats and `*.kdbx` are covered by the shared name policy. Tests separately check case-insensitive history exclusions.
- Git commands have no remote/network operation, checkout, user-defined alias invocation, external diff or textconv option. Existing marker tests exercise actual Git processes with synthetic hostile local settings; all executable payloads are harmless temporary-file markers.
- The installer keeps owner configuration keys, mixed hook groups, byte-preserving no-ops, backups, concurrent-edit detection and rename retries. It never runs a CLI. Every write in its tests targets a fake home.
- The tracker retains its bounded stdin/deadline, neutral agy `{}` reply, no permission decision, `AGENT_OFFICE_RUN` recursion guard, exact HMAC signature and prompt logging levels. Fake loopback servers bind ephemeral ports, not 3333/3334.
- Permission failures remain one needs entry through `finishCircuit`; non-permission failures do not log a need. Brain result propagation and circuit behavior retain their contract tests. No routes, golden fixtures or module-level server state were added.
- `--print-config` remains read-only and explicitly labels unverified MCP configuration formats.

## Limits and unverified behavior

- This is a filename-based secret policy. Secrets stored in innocently named content, commit messages, author fields, or other allowed project text are out of scope; this is not a content DLP scanner. Allowed project text remains untrusted prompt input and can contain instructions.
- Native Windows junction, file-symlink, ADS and delayed-expansion probes ran. This NTFS volume did **not** allocate an 8.3 alias in the native probe; the short-name syntax is rejected, but a real allocated alias could not be exercised. Non-Windows hosts have not been run; the POSIX FIFO regression is conditional and did not execute on Windows.
- Portable Node has no Windows directory-handle-relative `openat`/final-handle-path primitive. Descriptor identity and pre/post canonical checks stop the reproduced swap; this is **not** a proof against every adversarial multi-step parent-directory/reparse-point race. Installer checks also cannot make a whole parent-path walk and subsequent rename atomic against a separate malicious process.
- Linked worktrees (`.git` is a file), redirected/symlinked Git directories and bare repositories deliberately have no Git tool support in this pass. File tools fall back to a bounded walk. This avoids silently trusting project-controlled repository redirection; it is a compatibility restriction, not an installer change.
- Local Git configuration is still parsed, including local includes; the executed commands override relevant execution options and do not invoke remote transports or hooks. This review does not claim that Git's own parser, arbitrary future Git extensions, or a replaced Git/Node executable on a hostile PATH is sandboxed. Global/system configuration and inherited `GIT_*` overrides are suppressed.
- Exhaustive concurrency/fuzzing, every Windows reparse-point/device type, SMB authentication behavior, and maximum-volume filesystem stress were not verified. Log rotation is best effort under concurrent writers, not a transactional audit ledger. Oversized preexisting logs are refused rather than loaded or repaired.
- No real provider, CLI registration, hook trust state, installation contract or live configuration was exercised. Test PATH contains Node, Git and Windows system directories; serial shell-test reruns additionally include the local Python 3.13 executable directory. Optional installed-Claude plugin validation checks therefore skip. The existing `node_modules` junction is unchanged.
