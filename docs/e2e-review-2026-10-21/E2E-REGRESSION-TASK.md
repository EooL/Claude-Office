The previous run's report is `E2E-FULL-REPORT.md` (14 pass, 1 partial: responsive overflow) and its screenshots are in `e2e-full/`: compare against them.

## Journeys
1. **Re-run journeys 1-15 of `E2E-FULL-TASK.md`** (first run/access, services, settings tabs, chat basics, delegation, artifacts, provider failure, agents and scene, meters, incident, responsive/a11y, robustness, persistence, security smoke, real-provider smoke). For each: pass/fail/blocked, and a short "same as before / different" note against the previous report. Take a screenshot for every journey, including the ones that had none (security smoke: save the command output as a text file instead).
2. **J11 responsive, the fix under test:** at 1280x800 the layout must look exactly as in `e2e-full/j09-meters-payroll-memory.png` (same window position and size, nothing shifted or blurred); at 768x1024 and 390x844 there must be NO horizontal document scroll (`document.documentElement.scrollWidth <= clientWidth`) and the app must be fully visible and the chat input reachable (it is scaled down by design; nobody targets phones). Also at 1056x682 exactly and at 1100x700 (no scaling, no overflow). Resizing the browser window may not work in your tool; use same-origin iframes of each size if needed and say so.
3. **J16 new: office path routing, default office only.** `http://127.0.0.1:<port>/o/default/` must serve the same app as `/` (or the existing documented behaviour; record what it is); `GET /o/default/chat`, `/o/default/agents`, `/o/default/sessions`, `/o/default/settings` return the same data as the legacy paths; the WebSocket at `/o/default/ws` works like `/ws` (authenticated with the token as a subprotocol: trusted; without: read-only and redacted); `GET /o/off_abc123/chat`, `/o/..%2f/chat`, `/o/OFF_ABC123/chat`, `/o/default%2f..%2fchat` return 404 with `{"error":"Unknown office"}` (a uniform body), and bad `Host` / `Origin` still get 421 / 403 before anything else. Verify with fetch/curl-like calls and with one `WebSocket` from the browser page context.
4. **J17 new: secrets.** The token in `<E2E_HOME>\auth-token` unlocks the app and the signed `POST /event` of journey 8; a different random 64-hex token gets 401 on token routes and the read-only view on the WebSocket; the UI token is delivered only on a trusted socket.
5. **J18 new: restart with a stale registry file.** Create `<E2E_ROOT>\building.json` (set `AGENT_OFFICE_ROOT` to a temp dir for this one test) containing `{"schemaVersion":2,"offices":[]}` and start the server: it must refuse to start with a message naming the file and saying to delete it; delete the file: it starts normally. (Use a separate temp root; never the real `~/.claude-office`.)
6. **Console and network:** for every journey record any console error/warning and any failed request. A clean run has none besides the deliberate failures you provoke.
